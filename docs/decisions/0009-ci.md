# 0009: CI runs `make -C tests` on every push and pull request

**Status:** Accepted (approved by the project owner outside a spec; AGENTS.md
does not allow changes to `.github/` without one)

## Context

`.github/workflows/ci.yml` was committed empty, so GitHub reported
"No jobs were run" on every push.

## Decision

A GitHub Actions job runs `make -C tests`, the same command used locally,
on `ubuntu-22.04` (GCC 11) and `ubuntu-24.04` (GCC 13). It runs on pushes
to `main` and on pull requests. Both always run (`fail-fast: false`).

## Why

- The same command locally and in CI: nothing extra to keep in sync
- `make -C tests` already covers both the `-Werror` build and the
  sanitizer build, so CI checks everything a "Done when" list asks for
- `ubuntu-22.04` matches the development machine (GCC 11), so a failure
  there should also fail locally
- `ubuntu-24.04` adds GCC 13, which has warnings GCC 11 lacks. Under
  `-Werror` those are build failures that would otherwise only show up
  for someone with a newer compiler (this happened: a too-small
  `snprintf` buffer in `test_compile.c`)

## Consequences

Later specs that add tests (e.g. spec 0002) get CI coverage
automatically, as long as `make -C tests` runs them. Clang and the ESP32
toolchain are not covered yet. If Clang is added, use version 18 or
later: clang 14's AddressSanitizer crashes at random during startup on
kernels with high address randomisation (6.5+), which looks like a test
failure but is not.
